# Higgsfield quiz outcome animations

## Behavior

A live successful or failed quiz waits for its final battle action, then displays a four-second outcome scene. Victory uses golden star/laurel VFX; failure uses a quiet turquoise/lavender recovery ring. Higgsfield Seedance 1.5 Pro generated both scenery clips from the existing arena (job IDs and prompts in generation.json). The actual run companion is layered over the footage with a small CSS celebration/rest gesture; these clips do not generate individual creature performances.

Continue, correction, retry and home controls do not wait for the scene. Skip/replay only affect presentation. Historical results stay still. Reduced motion uses a JPEG poster. Leaving the scene or backgrounding ends playback, including backgrounding before the final battle action has finished; returning does not replay it automatically.

Media: silent 4-second H.264 Main / yuv420p / 960×540 / 24 fps MP4 with fast-start. iOS 15 and older route to two 480×270-cell JPEG atlases per scene, 32 frames at 8 fps, using the same Higgsfield footage. Rejected/stalled video falls back to these frames; total media failure leaves a poster and usable controls.

## Reproduction

Build the repository, run `node outputs/quiz-victory/fixtures.mjs` and `node outputs/outcome-motion/fixtures.mjs`. Serve the built app with `node outputs/quiz-victory/serve-qa.mjs` on port 49473. Run browser-qa.py with QA_URL=http://127.0.0.1:49473 and a Python Playwright environment with WebKit and Chrome installed.

prepare.py recreates runtime assets from the two original MP4 downloads named in generation.json (original downloads are intentionally not committed). verify-production.py compares deployed HTML/JS/CSS and all eight outcome assets byte-for-byte, then exercises the production frontend using intercepted synthetic APIs.
