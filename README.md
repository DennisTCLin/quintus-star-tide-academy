# 星潮學院・家庭整合版

以星潮學院的海洋世界、50 隻原創神獸和四年級題庫為主，整合注音航海團的錄音、主題圖片、注音題目及五位動物夥伴。玩家分別為 Quintus（四年級）、斐斐（二年級）、晴晴（一年級）、荳荳（一年級），各自保存進度。

## 啟動與驗證

需要 Node.js 22.12 以上。

```sh
npm ci
npm test
npm run build
DATABASE_URL=postgresql://localhost/star_tide PORT=4185 npm start
# 真實資料庫整合測試（獨立測試資料庫）
TEST_DATABASE_URL=postgresql://localhost/star_tide_test npm test
```

開啟 `http://localhost:4185`。開發時另啟動 API：`DATABASE_URL=... PORT=4197 npm start`，再執行 `npm run dev`（Vite 代理 `/api` 到 4197）。健康檢查為 `/health`、`/healthz`。既有 Dockerfile 與 railway.json 可直接建置，伺服器讀取 `PORT`，支援 CSP、gzip、媒體 Range 與音訊 MIME。

## 學習與閱讀

- 一年級：圖片、數量及注音作答，詞語題只呈現圖片選項；聽完錄音才開放作答，介面有圖示與朗讀。
- 二年級：中文與注音混合顯示；詞語、聲調、拼音、辨音及數學航線。
- 四年級：保留原學院國語、數學、英文、自然、社會題目及能力雷達。
- 每航程五題，答錯可以訂正，完成後選「試手氣」或「存一顆星」。練習模式不發完成獎勵。
- 當日每題只有第一次提交且答對才發 20 精熟點與 10 星幣；錯答後重開航程也不會重新取得獎勵。每天最多 15 道獎勵題。完成當日五題可選一次獎勵，每天最多三次；訂正也算完成，精熟點不花掉。
- 既有題目錄音在本站供應；其他導覽使用裝置的 zh-TW 語音。錄音載入失敗可重播，無語音引擎的裝置會顯示提示。
- 界面注音由靜態字典加上上下文修正產生。新增文案後以 `scripts/build-zhuyin.py` 重建（建置工具需求 `pypinyin==0.55.0`；網站執行不需要 Python），多音字需人工複核。題庫詞語優先採原站注音。

## 夥伴、星願、交換與對戰

共 55 位夥伴。收藏價格依 E / D / C / B / A / S / SS / SSS 為 300 / 600 / 1000 / 1600 / 2400 / 3600 / 5000 / 8000 星幣。原學院已解鎖的夥伴會保留。

三類技能：聚光每趟排除一個錯誤選項，對戰攻擊 +3；護盾展開提示，對戰首次傷害 −8；星火完整獎勵通關多 5 星幣，對戰回復多 5。夥伴有待機、鼓勵、答對、技能與攻擊動畫，支援減少動態。

完成五題後，「試手氣」有 50% 機會得到一張星願券；「存一顆星」一定加一顆，集滿兩顆自動換一張券。獎勵次數在完成時保留，尚未選擇時不可開始下一趟，重新登入或跨日仍可領取。每張券一定得到一張非初始夥伴卡，可重複；沒有星幣增減、十次保底或每日用券上限。隨機值與兌換都由伺服器交易處理，重送不會重抽。沒有付款功能。

交換由發起者選擇雙方各一隻夥伴，再切換到接收玩家確認；雙方必須先結束學習航程。初始潮光獸不能交換。庫存與裝備在單次保存內一起更新。

對戰支援電腦與同裝置雙人，雙方各 1–3 位夥伴且人數相同。所有夥伴體力均為 100，金剋木、木剋土、土剋水、水剋火、火剋金；有攻擊、防守、蓄能絕招、回復與換位。最多 60 次行動，之後比較剩餘體力。對戰不押注星幣、不奪走夥伴、不發獎勵。重新整理會結束未完成的對戰。

## 資料與遷移

現在以家庭帳號為單位儲存於 Railway PostgreSQL。四位航海員有各自的分數、卡片、星幣與航程；同帳號跨裝置共用，家庭成員可以切換四位玩家。沒有獨立兒童密碼或跨家庭公開排行榜。

每次操作由伺服器驗證登入、選項、餘額及 revision，在同一資料庫交易中更新家庭狀態與冪等收據。伺服器決定台北日期、題目與抽卡隨機值。成功回應代表已提交；可見分頁每約 3 秒更新，離線／失敗不發本機獎勵。重試使用相同操作編號，收據保存 30 天，過期請求仍由單調 revision 拒絕。完整題庫只在伺服器；瀏覽器取得當前題目，作答結算後才取得答案與解說。這不是無法作弊的承諾，練習可以重複作答。

首次登入空白帳號會偵測此裝置的 `star-tide.family.v1` 或更早的 `star-tide-academy.milestones.v2` 與夥伴鍵。確認歸屬後，一次轉入並保留原始鍵與資料庫中的原始快照，不需要下載檔案。已開始遊玩的雲端帳號不允許覆寫。舊分數、星幣、券與收藏保留為歷史資料；「雲端驗證的新精熟點」從零獨立累積。舊的進行中航程／交換不繼續；新版已完成且待領的獎勵和已存星星會保留，首次收藏日期設為未知，避免把歷史收藏算成今日取得。損壞格式拒絕轉入且保留原始資料。不同網域舊站的資料無法直接讀取，本次沒有假裝已遷移那些裝置上的資料。

帳號採 12–128 字元密碼、scrypt N=131072/r=8/p=1、Secure/HttpOnly/SameSite=Strict cookie（正式站）、CSRF token 與固定 Origin 驗證。session 最長 30 天、每帳號最多 10 個；復原碼一次有效，換密碼撤銷全部舊 session。登入後可確認密碼重新產生復原碼，處理首次回應遺失的情境。限流、最多兩個並行密碼雜湊、64 個同時 API 請求、8 個 DB 連線、1 MB body 與 SQL timeout 控制資源。登出／復原與交易用一致的帳號→session→狀態鎖順序。

## 部署與回復

正式站需設定 `DATABASE_URL` 和 `APP_ORIGIN=https://quintus-star-tide-academy-production.up.railway.app`。Docker 建置同時產生瀏覽器與伺服器題庫 bundle，資料保存在獨立 PostgreSQL volume，不能放在 web 容器檔案中。啟動會建立 additive schema；資料庫無法連線則啟動失敗，避免靜默退回本機存檔。

Railway PostgreSQL 已設定 PITR、每日與每週備份。維運者負責還原，不需家庭使用者管理遊戲進度備份。發布前需通過真實 PostgreSQL 整合測試、備份還原比對、兩個獨立瀏覽器與手機流程。正式還原應先到新服務驗證，再切換連線，不覆寫目前資料庫。

回復必須使用相容雲端 schema 的版本，保留 PostgreSQL 與已提交進度。首次雲端發布前的純本機版本不是有效回退目標；故障時維持明確不可用畫面並修復／前滾，不恢復瀏覽器寫入。下面各歷史發布紀錄記錄的是當時版本，舊備份操作說明不再適用本版。

## 技能戰鬥動畫與答題助戰（2026-10-24）

戰鬥依出招方、目標、屬性與技能播放衝刺、彈道、受擊、護盾、回復、換人與退場效果，並顯示本次實際傷害／回復數字。絕招依聚光、護盾、星火呈現不同特效；擊倒後先呈現原夥伴受擊，再切換下一隻。動畫期間鎖定操作，電腦等待動畫結束才行動；離開競技場暫停電腦回合。減少動畫使用獨立計時解鎖，不依賴 CSS 動畫完成事件。
