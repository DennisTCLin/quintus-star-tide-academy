# iPad 答題後下一題按鈕被裁掉

基底 `origin/main@457f4c0`；獨立分支 `codex/ipad-quiz-next-button`。Jeremy 數學島整合仍在原本的分支，本修正沒有混入該分支的未上線內容。

## 原因與重現

畫面上方的「好友對戰結果」是正常排版的 76px 橫幅。答題外框固定為視窗高度並隱藏溢出，但主區另外使用 100% 高度，沒有扣除橫幅。1024×748 下，主區底部落在 824px，「看懂了，下一題」位於 763～807px，整顆在畫面外。

答錯按鈕本來就會在答案保存後立即出現，沒有等待動畫或語音。好友已結束對戰僅保留在畫面十分鐘，之後橫幅消失，按鈕才重新露出，符合等待一段時間恢復的回報。

在 Chromium 與 WebKit 使用同一道颱風編號 202504 題、第 4／6 題、前三題答對及第四題答錯重現。實際本機 API 保存作答；好友提示採合成回應，未登入或修改真實孩子帳號。前後量測及截圖見 `output/ipad-next-button/`。

## 修改

- `src/quiz-console.css`：答題外框改為直向 flex，好友橫幅保留，主區取得剩餘高度。閱讀區保留至少 64px；極短畫面可捲動題目與選項區，下一題按鈕留在該捲動區之外。
- `src/App.tsx`：以主區實際剩餘高度計算競技場預算，監聽主區大小，處理好友提示出現／消失與旋轉。ResizeObserver 量測透過 requestAnimationFrame 合併，離開時取消排程，避免觀察回呼內反覆改變尺寸。
- 判分、作答、換題、獎勵、權限、好友狀態、存檔版本及所有伺服器程式均未變更。未增加自動關閉或忽略好友邀請的行為。

## 重跑方式

僅建立並使用獨立 localhost 測試資料庫 `star_tide_ipad_next_20261026`，不得改成正式連線。設定任意四位數測試密碼於 `QA_PASSWORD`；先建置，再以 `output/ipad-next-button/start-local.mjs` 建立全新合成帳號並啟動 47829 埠服務，接著執行同目錄 `browser-check.py`。腳本會重設該合成帳號的測試快照與本機限流紀錄以便重跑；不可用於其他資料庫。`reproduce.py` 用於原基底建置，故預期修正後不再符合其「按鈕在畫面外」斷言。
