# 六年級換科入口修正

基底：`dc73b97`（含尚未發布的 iPad 下一題版面修正）。本分支不含 Jeremy 數學島整合，不修改或部署 main。

## 問題與查證

家長最初寫曾崇碩，後確認為曾博聖的 Alston 帳號。2026-10-26 以唯讀資料庫交易檢查正式帳號：目前為自然科挑戰失敗、錯題待補練。僅在記憶體複本移除該趟阻擋後，五科皆可正常建立六題挑戰；並非其他科目的題庫被停用。沒有修改玩家資料、登入玩家帳號或使用玩家密碼；臨時診斷 SSH 公鑰已撤銷。

在獨立 localhost 資料庫建立相同學習階段的合成帳號，重現「換個科目」視窗只剩「繼續挑戰」、科目選項為零，見 `output/alston-subject-entry/before.json`。這證實換科入口有缺陷，但不能斷言已重現家長提到的每一條「只剩數學可點」操作路徑。

## 修正

- 有未完成挑戰、待補練或待領獎勵時，選科視窗仍顯示該年級所有科目，另保留回原挑戰的入口。
- 選科沿用首頁島嶼相同的 `selectIsland` 流程：同科接續、換科先確認、待領獎勵先結算、數學島先結束或結算。
- 進入換科確認時關閉選科視窗，避免兩個原生 dialog 疊在一起。直接開始失敗則保留選科視窗與錯誤提示。
- 執行時只改 `src/App.tsx`。不改伺服器判分、帳號、題庫、存檔格式或獎勵規則。

## 驗證與限制

正式建置通過；813 項測試通過，175 項資料庫測試在一般測試指令中略過。另以真實本機 API 完成 30 組換科流程及 8 組結算／拒絕請求檢查，一般操作無瀏覽器錯誤。低年級數學島保護規則既有單元測試通過；其選科視窗端到端流程本次未重跑。

測試紀錄與腳本：`output/alston-subject-entry/`。測試以獨立 PostgreSQL、合成帳號與真實 localhost API 執行；測試登入名稱配合校籍對照表，並非登入正式帳號。

瀏覽器使用 Chromium / WebKit 觸控環境，在 1024×748、768×940、393×740 驗證換科、取消、同科接續、重新整理、玩家隔離，以及保留星幣、夥伴、經驗與精熟紀錄。另驗證待領獎勵、已完成挑戰、進行中挑戰及拒絕請求。實體 iPad 尚未驗證。

WebKit 若在刻意重新整理／關閉頁面時取消 `/api/state`，單獨記錄為 navigation cancellation；一般操作錯誤不予忽略。

不包含另行發現的「題庫不足提示位於首頁上方」改善；本次正式帳號五科皆有足夠題目，故不把該情境當作已證實根因。

尚未部署正式環境。回復時可單獨 revert 本次換科提交，不影響基底的 iPad 下一題修正。
