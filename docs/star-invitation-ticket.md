# 星耀特邀券

管理員特別贈送的獨立扭蛋券。每張抽一位夥伴：S 30%、A 70%，不含 SS／SSS 或其他階級。每次獨立抽選、沒有保底，可能重複。相同階級內等機率，初始夥伴不在卡池。一般星願券 S 1% 與其他機率、新手扭蛋、答題獎勵都不變。

票面以深海藍、金色星章、切口與虛線票根呈現；文字與機率由 HTML/CSS/SVG 畫出，縮放清晰且不增加圖片下載。扭蛋頁提供券種單選、餘額、獨立機率表與扣券確認。結果保存券種。

## 管理員發放

現有網站沒有管理員角色。沿用帳號建立工具的管理模式，僅持有部署資料庫權限的管理員可操作；沒有玩家或家長可呼叫的發券 HTTP API。管理員姓名是稽核標記，並非憑證，真正的權限由資料庫存取控制。

部署環境內先預覽（或在本機設定受保護的 DATABASE_URL 並先 npm run build:server）：

```sh
node server/star-ticket-admin.mjs \
  --username alan \
  --amount 1 \
  --grant-id 00000000-0000-4000-8000-000000000001 \
  --reason '管理員活動獎勵' \
  --operator '管理員名稱'
```

以上僅為範例，未實際給任何玩家發券。每次新發放使用新的 UUID（例如 node -e 'console.log(require("node:crypto").randomUUID())'），同一筆重試必須保留原 UUID。確認預覽的玩家姓名／帳號／餘額正確後，加 `--apply` 執行同一指令。單次 1–100 張，餘額最多 10,000 張。

工具以 player_logins.username 找到唯一真實玩家，不用年級共用的 profile 名稱識別人。資料庫交易鎖住該玩家家庭進度，只更新目標的 starTickets 與 revision；永久 star_ticket_grants 表保存發放編號、對象、原因、操作者與前後餘額。相同編號重試回傳原紀錄、不重發；改內容會拒絕。預覽已發編號也會回報原紀錄。

玩家確認同步或重新整理後可在扭蛋頁看到券。發放不登入玩家帳號、不代替玩家抽卡。一般券不能兌換此券，備份匯入會清除非伺服器核發的特邀券。

## 驗證與回復

新增欄位對舊存檔預設為零。沒有變更原有點數、收藏與學習資料。伺服器使用既有 session/CSRF、玩家隔離、revision、操作收據與交易鎖；亂數由伺服器產生，重試不會重扣。發券與抽券共用 game_states 鎖避免同時覆寫。

- 完整實際 PostgreSQL 回歸：110 檔、799 項通過。
- 最終管理員預覽修正後：3 檔、35 項通過，包含永久發券重試／拒絕內容變更、假備份、偽造操作、抽券重試及舊存檔。
- 枚舉 10,000 個機率區間：特邀 A 7,000／S 3,000；一般機率不變。
- Chromium 320px 真實測試帳號：取消不扣券、抽特邀券 3→2、一般券維持 2、保存券種，無水平溢出。
- WebKit 行動模式一年級 320px：無水平溢出、抽完券歸零、一般券不變、空券停用、重新載入仍有抽卡收據；屬瀏覽器模擬，未聲稱實體 iPhone 測試。
- 獨立唯讀複核通過，預覽重試問題已修正並再複核。
- 視覺驗證與正式部署證據見 output/playwright/star-ticket/。未對真實玩家發券。

回復程式可停用特邀券入口及 draw-star，保留餘額與永久發放收據，不能刪表或重置玩家資料；不要在尚未包含此功能的舊部署上執行發券工具。
