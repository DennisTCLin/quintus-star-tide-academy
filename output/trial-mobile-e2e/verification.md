# 手機與 iPad 試用帳號完整流程驗證

2026-10-27。資料全部來自隔離本機 PostgreSQL，由實際後台表單建立；未建立正式站 QA 玩家或修改孩子資料。測試使用正式建置產物及真實本機 API，不以攔截結果代替建立、抽卡、作答或降服。

## 結果

- `results.json`：Chromium 393×852、820×1180、1180×820；WebKit 393×852、768×1024、1024×768，6 組完整流程 PASS。
- 每組：超管表單建立小六帳號（5000 星幣／20 星願券／5 特邀券）→新帳號登入→實際抽一張卡（只扣一張星願券）→六題實際作答→新怪物三題全對降服→收藏與額度刷新後保存。
- 每組在第一題刻意攔住背景 GET，於同步中點答案，確認寫入等待 GET 完成。一般新題與降服題的未作答答案仍被伺服器遮蔽；測試正解從本機題庫查詢，不新增除錯 API。
- 每組在降服第一題答對後重新整理，再完成剩餘兩題；降服階段不重複發星幣／票券。
- `extended-results.json`：WebKit 手機393×852、Chromium橫向1024×768，正常動畫偏好、一般券＋特邀券各抽一次、六題戰鬥、降服第二題答錯立即結束，2 組 PASS。確認未獲得怪物，原有戰鬥獎勵保留。
- 操作採觸控 tap，檢查關鍵按鈕中心未被遮擋、觸控高度與頁面無橫向溢出。截圖留在本機 screenshots/（不入 Git）。

## 發現與修正

原版在 iPad 橫向快速操作時，背景讀取與答案寫入共用 `inFlight`，會把可點選答案擋成「正在同步，請稍後再試」。`src/cloud.ts` 現在只讓動作等待既有的被動讀取完成，再使用最新 revision 送出。主動寫入仍排他；失敗讀取、離線、帳號切換及尚未核對的未知命令，仍阻止新寫入。沒有更動後端判分、帳號、schema、獎勵與降服規則。

新增9項可控時序測試；加上原有3項transport測試，共12項 PASS。修正原基線全測試938 PASS／192 DB gated skip，build PASS。接上學伴固定位置 main df07029 後，全測試933 PASS／192 skip，build PASS；數量差異來自上游 PR11 移除5項舊浮動位置測試。合併後再跑 WebKit 手機393×852與iPad橫向1024×768，2組完整實際API流程 PASS（merged-results.json），含同步重疊點擊、降服中續玩與保存。

冷複查以 read-only 檢查等待讀取、並行寫入、未知回覆恢復、session epoch、離線與舊render callback，未發現可重現反例。

## 重跑與範圍

先 `npm run build`，執行 `node output/trial-mobile-e2e/serve-local.mjs`，再用安裝 Playwright 的 Python 執行 check.py、check-extended.py；合併PR11後的手機／iPad二組回歸為 check-merged.py。server 僅連本機55432，建立自己命名的臨時資料庫，收到SIGTERM/SIGINT後刪除該資料庫。共用 PostgreSQL 不停止。全部帳密為合成資料。

大量重跑曾觸發隔離資料庫原有超管登入10次／10分鐘限制，已換新隔離資料庫完成最後驗證；未降低產品登入限制。

正式站原有發布來源452ecda的17個編譯／代表媒體檔案 hash、health與匿名401保護另重驗通過（production-assets.json）。修正待與PR11協調同一次發布；發布結果另記錄，這項基線檢查不代表修正已上線。
